# 🔧 Синхронизация Parsing - Подробная документация

## 📋 Описание

Функция **"Перезаписать Parsing"** позволяет автоматически синхронизировать данные parsing из основного конфига во все сезонные конфиги с гибким выбором полей для синхронизации.

## 🎯 Назначение

Эта функция решает проблему ручного копирования данных о конкурентных отелях между конфигами. Вместо того чтобы вручную добавлять/удалять/изменять отели в каждом сезонном конфиге, вы можете сделать это один раз в основном конфиге и автоматически синхронизировать изменения.

## 🚀 Как использовать

### Шаг 1: Открыть модальное окно
1. Нажмите на кнопку **"🔍 JSON Search & Replace"** в правом верхнем углу
2. Нажмите на кнопку **"🔧 Перезаписать Parsing"**

### Шаг 2: Выбрать поля для синхронизации
В открывшемся окне вы увидите:

#### Обязательные поля (синхронизируются всегда):
- ✅ `standart_category` - категории номеров
- ✅ `hotel_title` - название отеля

#### Дополнительные поля (выберите нужные):
- ☑️ `concurents_influence` - влияние конкурента
- ☑️ `take_max_price` - брать максимальную цену
- ☑️ `force_rate` - принудительный тариф
- ☑️ `force_key` - принудительный ключ
- ☑️ `new_id` - новый идентификатор
- ☑️ `genius` - настройки Genius
- ☑️ `tax` - налоги
- ☑️ `tax_per_person` - налог на человека
- ☑️ `stay_length` - длительность проживания
- ☑️ `price_source` - источник цены
- ☑️ `clip` - обрезка значений

### Шаг 3: Запустить синхронизацию
1. Отметьте нужные дополнительные поля
2. Нажмите кнопку **"Синхронизировать"**
3. Дождитесь завершения процесса

## 📊 Что происходит при синхронизации

### 1. Поиск конфигов
Скрипт автоматически находит:
- ✅ **Основной конфиг**: `price_sources_hotels-0-config`
- ✅ **Сезонные конфиги**: все конфиги с `hotelSeasonsConfigs` в ID

### 2. Синхронизация данных

#### Для каждого элемента parsing:
```json
{
  "parsing": {
    "selfID": "bnovo_xxxx",  // ← Сохраняется без изменений
    "concurents": [           // ← Синхронизируется
      {
        "hotel_id_1": {
          "standart_category": [...],  // ← Синхронизируется всегда
          "hotel_title": "...",         // ← Синхронизируется всегда
          "concurents_influence": 1     // ← Синхронизируется если выбрано
        }
      }
    ]
  }
}
```

### 3. Операции синхронизации

#### ➕ Добавление новых отелей
Если в основном конфиге есть отель, которого нет в сезонном:
```
Основной: [hotel_A, hotel_B, hotel_C]
Сезонный: [hotel_A, hotel_C]
Результат: [hotel_A, hotel_B, hotel_C]  ← hotel_B добавлен на позицию [1]
```

#### 🔄 Обновление существующих отелей
Если отель есть в обоих конфигах, обновляются только выбранные поля:
```
Основной:  hotel_A { title: "New", influence: 2 }
Сезонный:  hotel_A { title: "Old", influence: 1, custom: "value" }
Результат: hotel_A { title: "New", influence: 2, custom: "value" }
           ↑ выбранные поля     ↑ не выбранные поля сохраняются
```

#### ❌ Удаление лишних отелей
Если в сезонном конфиге есть отель, которого нет в основном:
```
Основной: [hotel_A, hotel_C]
Сезонный: [hotel_A, hotel_B, hotel_C]
Результат: [hotel_A, hotel_C]  ← hotel_B удален
```

### 4. Сохранение порядка
**Важно!** Порядок элементов всегда берется из основного конфига:
```
Основной:  [hotel_A, hotel_B, hotel_C]
Сезонный:  [hotel_C, hotel_A, hotel_B]
Результат: [hotel_A, hotel_B, hotel_C]  ← порядок как в основном
```

### 5. Сохранение уникальных данных
- ✅ `selfID` каждого конфига остается без изменений
- ✅ Не выбранные поля не изменяются
- ✅ Дополнительные поля из сезонных конфигов сохраняются

## 🐛 Debug режим

### Как просмотреть логи:
1. Откройте консоль браузера (F12)
2. Перейдите на вкладку "Console"
3. Следите за логами в реальном времени

### Что показывают логи:

#### INFO логи (всегда видны):
```

```

#### DEBUG логи (только в debug режиме):
```

```

## 📈 Примеры использования

### Пример 1: Добавление нового конкурента
**Ситуация:** В основном конфиге добавлен новый отель Booking.com

**Действия:**
1. Добавьте отель в основной конфиг
2. Нажмите "🔧 Перезаписать Parsing"
3. Выберите поля: `concurents_influence`, `take_max_price`
4. Нажмите "Синхронизировать"

**Результат:**
```
Все сезонные конфиги: добавлен новый отель на той же позиции
Синхронизировано полей: 2 (standart_category, hotel_title + выбранные)
Время выполнения: ~5 секунд
```

### Пример 2: Удаление конкурента
**Ситуация:** Отель Expedia больше не является конкурентом

**Действия:**
1. Удалите отель из основного конфига
2. Нажмите "🔧 Перезаписать Parsing"
3. Нажмите "Синхронизировать" (можно не выбирать доп. поля)

**Результат:**
```
Все сезонные конфиги: отель удален
Время выполнения: ~3 секунды
```

### Пример 3: Обновление влияния конкурентов
**Ситуация:** Нужно изменить `concurents_influence` для всех отелей

**Действия:**
1. Обновите значения в основном конфиге
2. Нажмите "🔧 Перезаписать Parsing"
3. **Обязательно выберите** `concurents_influence`
4. Нажмите "Синхронизировать"

**Результат:**
```
Все сезонные конфиги: обновлено поле concurents_influence
Остальные поля: остались без изменений
```

### Пример 4: Массовое переименование отелей
**Ситуация:** Изменились названия отелей-конкурентов

**Действия:**
1. Обновите `hotel_title` в основном конфиге
2. Нажмите "🔧 Перезаписать Parsing"
3. Нажмите "Синхронизировать"

**Результат:**
```
Все сезонные конфиги: обновлены названия отелей
Синхронизировано автоматически (hotel_title - обязательное поле)
```

## ⚠️ Важные замечания

### Что НЕ изменяется:
- ❌ `selfID` каждого конфига
- ❌ Поля, не выбранные для синхронизации
- ❌ Дополнительные пользовательские поля

### Что изменяется:
- ✅ Все выбранные поля во всех concurents
- ✅ Порядок элементов (берется из основного)
- ✅ Список отелей (добавление/удаление)

### Безопасность:
- ✅ Валидация JSON после каждого изменения
- ✅ При ошибке валидации изменения не применяются
- ✅ Подробные логи всех операций
- ✅ Возможность отследить каждое изменение

## 🚨 Устранение неполадок

### Проблема: Синхронизация не находит конфиги
**Решение:**
1. Убедитесь, что вы на странице редактирования отеля
2. Проверьте, что JSON редакторы загружены
3. Обновите страницу (F5)

### Проблема: Поля не синхронизируются
**Решение:**
1. Убедитесь, что выбрали нужные поля в чекбоксах
2. Проверьте логи в консоли (F12)
3. Убедитесь, что поля есть в основном конфиге

### Проблема: Ошибка валидации JSON
**Решение:**
1. Проверьте основной конфиг на корректность JSON
2. Проверьте логи в консоли для деталей
3. Исправьте ошибки в JSON вручную

### Проблема: Синхронизация слишком долгая
**Решение:**
1. Это нормально для большого количества конфигов
2. Дождитесь завершения (не обновляйте страницу)
3. Проверьте результат в логах

## 💡 Советы по использованию

### 1. Используйте Debug режим
Всегда включайте debug режим для первой синхронизации, чтобы убедиться, что все работает правильно.

### 2. Выбирайте только нужные поля
Не выбирайте все поля сразу. Синхронизируйте только те, которые действительно нужно обновить.

### 3. Проверяйте основной конфиг
Перед синхронизацией убедитесь, что основной конфиг содержит корректные данные.

### 4. Делайте резервные копии
Хотя скрипт валидирует JSON, рекомендуется иметь резервную копию конфигов перед массовыми изменениями.

### 5. Используйте пошагово
Для больших изменений лучше синхронизировать по одному полю за раз, чтобы легче было отследить изменения.

## 📊 Производительность

- **Скорость обработки**: ~10-20 конфигов в секунду
- **Оптимизация**: Использование Map для быстрого поиска
- **Валидация**: Проверка JSON перед каждым сохранением
- **Логирование**: Минимальное влияние на производительность
